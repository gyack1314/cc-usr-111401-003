# 资料与既有接口约定

日志项含 epoch、offset、previous、manifest；previous 是前项规范摘要，首项 previous=null。manifest 列出全部对象 SHA256，不以文件名相同推断内容相同。通道分别递送日志及对象，可乱序和重复。接管授权来自本地 authority.json，包含递增 epoch 和允许持有者，非网络选举协议。接收端只能在已授权世代上推进；世代切换须以明确基准提交相接。replica.py 独立落地消息和对象；receiver.py 在其上提供可读头、副本推进与接管。

副本推进与接管协议（warehouse/receiver.py）：

- 版本完整才可读：日志项的 manifest 是该版本的全部对象闭包。只有当前授权世代从基准起连续、前驱摘要相符、闭包内对象全部通过摘要校验，可读头才推进到该位置；对象未校验完时保留上一版可读头，不拼接新旧目录。
- 读句柄：open_handle 固定当前可读头，世代号持久递增、重启连续；句柄读取按其登记摘要解析，不受后续推进影响。
- 接管：takeover 依次登记本地授权记录中的下一个递增世代，要求基准提交（上一世代 base_offset 位置）已本地完整，否则返回 blocked 及尚缺材料。登记后旧世代日志一律视为 stale，只留证据不推进正式分支；旧世代位置上的分叉内容同样只登记证据（stale_fork），不影响正式分支。
- 分叉：正式分支同一 epoch:offset 出现不同内容即登记 fork 并停止推进，重启后仍然停止，不按到达先后选赢家。
- 证据：evidence.jsonl 按序记录接收、重复、stale、断链、推进、句柄与接管事件，重启后仍可读取。
- 落后说明：status 与 takeover_report 明确列出未完整项、缺对象与缺位置；未收到部分一律标记 unknown，不承诺尚未收到的数据也能零损失恢复。

所有资料均为合成，字段、身份及状态按本文解释。源码中的 inspect 入口只读取并核对现有基础接口；不会建立高级查询或仓库管理流程。
